# Exigências da avaliação AV03

Fonte: PDF AV03 fornecido pelo responsável pelo projeto em 16/11/2026. Este arquivo resume critérios de avaliação; não cria novos requisitos do sistema comunitário.

## Obrigatório

- Linguagem com orientação a objetos. O documento lista Java, C#, Python, PHP, Kotlin e TypeScript como exemplos; não impõe uma linguagem específica.
- Persistência em banco com SQL puro ou ORM/framework. Hibernate/JPA e outros são exemplos permitidos.
- No mínimo sete funcionalidades completas, cada uma com fluxo completo, persistência e regras de negócio implementadas.
- Documentação em Markdown, `prd.md` junto ao código, arquivo de arquitetura e `specs/**.md`.
- Registrar as skills usadas, se possível.
- Código-fonte em repositório **público** no GitHub ou GitLab e script do banco de dados na entrega.

Os exemplos de produtos, estoque, dashboard e agendamento no PDF não pertencem automaticamente ao nosso projeto.

## Pesos

| Critério | Peso |
|---|---:|
| Complexidade das funcionalidades / sete funcionalidades | 20% |
| Conexão com banco e compreensão de ORM/SQL | 10% |
| Compreensão dos pilares de POO | 60% |
| Apresentação | 10% |

## Checklist da entrega

- [ ] Pelo menos sete funcionalidades realmente completas e demonstráveis; conferir dependências e regras transversais.
- [ ] Equipe explica encapsulamento, abstração, herança e polimorfismo no código produzido.
- [ ] PostgreSQL persiste e recupera dados dos fluxos.
- [ ] `prd.md`, `arquitetura.md` e specs refletem a implementação final.
- [ ] Script SQL de entrega atualizado e testado em banco vazio.
- [ ] Repositório público acessível ao professor, sem segredos nem dados reais.
- [ ] Os dois integrantes conseguem apresentar e explicar o projeto.

O modelo de PRD e o exemplo de arquitetura mencionados como apresentados em sala não vieram no PDF. Se o professor exigir exatamente esses modelos, comparar com os exemplos antes da entrega. O PDF fornecido não informa data de entrega nem exige um provedor específico de mensagens.
